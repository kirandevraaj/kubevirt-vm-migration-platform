05

What is a VM? More than a disk

COMPONENTSRISK: NETPLAN

A VM has virtual CPU, memory, firmware, NIC, disk and a guest OS. Only the disk bytes are copied. Everything else is re-created on the target, so any guest setting tied to VMware hardware becomes a risk.

06

VMDK anatomy

OBSERVED 1D

The .vmx is reference only and the .nvram is not carried. The VMDK is a small text descriptor plus a 40 GiB data file that holds the real guest disk: GPT, an EFI partition and ext4 root. That data file is locked while the VM runs.

13

KubeVirt mental model

CONCEPT / DESIGN — NOT DEPLOYED

CDI puts the disk into a PVC (import or upload, stored raw). KubeVirt runs the VM: VirtualMachine, then VMI, then a virt-launcher Pod with QEMU on KVM. The PVC is where one hands over to the other. CDI never runs the VM.

Understand what actually changed

The mechanics behind each lesson.
07

Why a cold copy?

OBSERVED 1D + 1E

While the VM runs, its disk cannot even be read, and snapshots are not allowed. So: shut down, copy, and hash three times. Matching hashes prove the copy is exact and the source was not touched. The numbers are lab observations, not benchmarks.

08

Protect the golden artifact

OBSERVED 1E-1G

The golden copy is never touched. One immutable working copy feeds both conversions, and each conversion writes to a new directory. Fixes go onto a separate disposable copy. Boot tests run on throwaway overlays, and disk bytes only ever flow one way.

09

qemu-img vs virt-v2v

MOST IMPORTANTOBSERVED 1G

qemu-img only repackaged the disk: the guest bytes are identical. virt-v2v changed the guest: it removed VMware Tools, rebuilt the initramfs, added a first-boot job and wrote libvirt XML. Both booted under KVM. Neither fixed netplan, so neither had a network.

10

The hardware change

OBSERVED 1GRISK

The disk moves from sda to vda, but mounts use UUIDs, so it still works. The NIC moves from ens192 to enp0s3, but netplan still asks for ens192, so it breaks. The interface name under KubeVirt is not tested yet.

11

The network failure and the lab proof

FAILURELAB PROOFADR 010 DESIGN

After conversion the guest is healthy but unreachable. On a disposable copy, matching the NIC by driver (virtio_net) fixed it. The lab test used a static test address, 10.0.2.15, on an isolated network, and got HTTP 200 with the same page hash. DHCP is the target design (ADR 010), not what the lab test used.

12

The UEFI story

OBSERVED 1GSECURE BOOT ON: NOT TESTED

Firmware settings live in the VM, not on the disk. With a fresh, empty variable store, OVMF found the disk's fallback loader (BOOTX64.EFI, which is shim), then GRUB, then Ubuntu. The VMware .nvram was not needed. Secure Boot was off throughout.

14

Target network

DESIGN (ADR 008)

In KubeVirt the guest sits behind its Pod (masquerade) and gets 10.0.2.2 by DHCP. Clients reach it through a NodePort Service. The old address 192.168.50.31 does not follow it; the proof of success is the same page content.

15

Target storage

DESIGN (ADR 009) — NOTHING PROVISIONED

The design moves the prepared qcow2 (about 2.7 GiB) to the node, uploads it through CDI, and stores it raw on a 40 GiB gp3 Block PVC. Only the golden VMDK and the 1G virt-v2v output exist today. Everything else is design.

17

What changed?

PROVEN 1GDESIGN 1H

The hypervisor, VM process, devices and firmware changes were proven under QEMU/KVM in 1G. The manager, network, VM definition and storage changes are design only. The guest's identity and content stayed the same.

18

Migration vs modernization

MIGRATION: STAGE 1 PATHMODERNIZATION: FUTURE

Migration keeps the whole VM and changes only its manager. Modernization takes the application out of the VM and runs it as containers. Stage 1 worked only on the migration path; modernization is a later, separate step.

REMEMBER

5 things to remember

1

A VM is more than its disk.

2

KVM is the kernel virtualization engine; QEMU creates the VM.

3

Changing VMware hardware to VirtIO can break guest configuration.

4

qemu-img changes the disk container; virt-v2v can change the guest.

5

KubeVirt puts the VM lifecycle under Kubernetes.
